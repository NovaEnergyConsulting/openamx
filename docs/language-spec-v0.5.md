# OpenAMX V0.5 Product and Report Contract (Approved 2026-09-30)

This is the authoritative V0.5 additive product/report contract, approved by the Lead Developer on 2026-09-30 as recorded in planning. V0.2, V0.3 and V0.4 specifications retain authority over their existing language, input, view and export semantics. Normative words `must`, `may` and `must not` describe implementation requirements, not features already shipped. The [visual-review manifest](../planning/sprints/0028-v05-product-ux-branding-compatibility-contract/visual-review.md) is the approved companion acceptance instrument. The Sprint 028 gate is satisfied for Sprints 029, 031 and 033; 030 depends on 029, 032 on 031, and 034 on 029-033.

## 1. Baseline and Compatibility

The existing desktop `.openamx/project.json` accepts `{ "version": 1, "inputs": { "name": "relative/path.json" } }` only; missing config supplies no defaults, unknown keys are errors, and per-run > ignored `.openamx/local.json` > project input mappings. CLI input paths remain relative to the process working directory. Existing YAML frontmatter is a mapping; `title` (string) supplies the HTML/PDF/DOCX title, otherwise `OpenAMX Document`. HTML renders each executable fence as escaped canonical formatted AMX source, then the fence's `show` emissions in statement order. PDF and DOCX likewise render visible source in document order. Final narrative interpolation uses the final evaluated environment; immutable views capture show-time data. Desktop run/preview use unsaved entry text in a file-backed main-process session; export writes are preflighted and atomic. None of those rules changes by default.

| Document/config | V0.5 identity/source behavior | Preserved behavior |
| --- | --- | --- |
| V0.2 only, no new fields | neutral identity, source visible | V0.2 fences, evaluation, interpolation and formatting |
| V0.3 only, no new fields | neutral identity, source visible | module/input/output validation and CLI mapping semantics |
| V0.4 views, no new fields | neutral identity, source visible | show-time snapshots, original source/view order, HTML interactions and static export data |
| Any above with `report` fields | validated identity and explicit visibility only | all language/data/view semantics and safe writes |

V0.5 presentation may change visual styling, not emitted values or source/view order. No default source-hiding migration is authorized. Old version-1 input files remain valid without editing. No second document parse/check/module or input load/evaluation pass may be introduced by a report adapter; analysis, inputs and identity assets are prepared by the trusted caller before any output destination is changed. The trusted shared preparation resolves each narrative interpolation against the final environment once and produces immutable ordered content and identity; HTML/PDF/DOCX only serialize that result, with `viewEmissions` indexed by document node/statement. Interpolation errors fail preparation before writes. A hidden source fence removes only the formatted listing, not its emissions, narrative position or data alternatives. No interactive table state enters print/export.

## 2. Portable Identity Schema

The project file remains **version 1** with required `version: 1` and required `inputs: { [logicalName]: string }`; V0.5 allows one optional top-level `report` object. Existing `inputs` validation, path bases, 100 mapping limit, local/per-run override and invalid-config behavior remain intact. `.openamx/local.json` retains only `version` and `inputs`; it cannot override report identity. CLI `render` and `export pdf|docx` gain optional `--project-root <dir>` to select a canonical existing directory and read its `.openamx/project.json` report defaults; absent that option no project config is read, but frontmatter identity without a logo still applies. CLI `run` remains unchanged. This flag does not supply CLI input mappings, change their process-working-directory base, or discover parent projects. In desktop, the selected canonical open project is the identity root. The project root for identity assets is the canonical selected project directory, not the entry file directory. Without an explicitly selected project root, a frontmatter logo cannot resolve and is an error.

The sole additive report-level YAML frontmatter key is `report`, a mapping with the same fields as project `report`. `title` remains the existing top-level string metadata; `report.title` is not supported. Other historical frontmatter keys remain inert. Unknown keys inside either `report`, and unknown project root keys, are errors when the corresponding config is selected for rendering/export; unknown top-level YAML keys remain inert for compatibility. Duplicate keys in either report mapping or the project JSON root/report object are errors (no last-key-wins). No `null`, empty string, implicit YAML Boolean/number, arrays or nested objects are valid field values except the Boolean `sourceVisible`. YAML strings must be explicitly quoted where YAML would otherwise infer a different type. Absence means inherit; explicit clearing is not supported. Maximum text lengths count Unicode code points after parsing; reject controls except ordinary space (and no newline), bidi controls, and invalid Unicode. Trim outer whitespace before length checks; reject empty results. The only accepted field names and values are:

| Field | Type / validation | Neutral default |
| --- | --- | --- |
| `organization` | string, 1-120 code points | absent (no publisher line) |
| `logo` | POSIX-style project-relative string, 1-240 ASCII characters; see section 3 | absent |
| `logoAlt` | string, 1-120 code points; required when `logo` is present in the effective identity | absent |
| `accent` | string matching `^#[0-9A-Fa-f]{6}$` | `#146C94` |
| `author` | string, 1-120 code points | absent |
| `status` | string, 1-80 code points | absent |
| `classification` | string, 1-80 code points | absent |
| `footer` | string, 1-300 code points (legal notice may be included) | absent |
| `sourceVisible` | Boolean | `true` |

Report frontmatter overrides project report defaults **field by field**, then neutral defaults apply. `logoAlt` follows the effective logo: a frontmatter `logo` override without `logoAlt` must supply a new frontmatter `logoAlt` rather than inherit the project's description of a different image. If `logoAlt` is given without an effective logo it is invalid. Neither file may contain absolute/drive/UNC/private paths, credentials, URLs, CSS, HTML, fonts, scripts or arbitrary asset references. Names/status/classification/footer are plain text, never trusted markup. `status` and `classification` are free-text labels, not access controls, security markings, workflow state or permission grants. Source hiding is presentation only, not a confidentiality boundary: original AMX, input data, view alternatives and exported documents can still disclose content. UI must label the setting accordingly.

```json
{"version":1,"inputs":{"screenings":"data/screenings.csv"},"report":{"organization":"Example Utilities","logo":"assets/logo.png","logoAlt":"Example Utilities logo","accent":"#146C94","footer":"Copyright Example Utilities","sourceVisible":true}}
```

```yaml
---
title: Transformer review
report:
  author: "A. Analyst"
  status: "Draft"
  sourceVisible: false
---
```

The example retains `inputs.screenings` precedence exactly as before; frontmatter only changes author/status/source visibility for this report. To migrate an existing version-1 file, leave `version` and `inputs` untouched and optionally append `report`; existing documents require no migration. To recover provenance when an opt-in document hides source, remove `sourceVisible: false` or set it to `true`. Explicit `true` in frontmatter overrides project `false`. HTML has a semantic source section for visible listings, PDF has selectable code text, and DOCX has editable source paragraphs; when hidden, all omit the listing but retain views after the owning fence. Do not promise identical pagination or pixels.

## 3. Validation, Diagnostics and Assets

Validate project config structure and frontmatter syntax/fields first, then resolve identity and local assets, then prepare all three adapters' content before any requested report write. Invalid project identity fails the report operation even if a frontmatter override would mask it; no fallback to a different config value. Diagnostics use `AMX6001` for config/metadata/path validation and `AMX6002` for asset decoding/adapter serialization failures; retain historical AMX400x for inputs. A project diagnostic identifies `.openamx/project.json` plus RFC 6901 JSON pointer (for example `/report/accent`); frontmatter errors identify entry file plus original one-based line/UTF-16 column of the offending YAML key/value (including the opening delimiter), or the `report` key for a missing dependent property. A missing project root for a logo is `AMX6001` at `/report/logo` or its YAML location. Errors carry bounded neutral messages, never local override paths, input contents or credentials. Error order: project keys in file order, YAML report keys in source order, then effective logo/contrast checks; abort before output writes. One error may be reported first; do not silently skip any selected invalid field.

`logo` must use forward slashes, no leading slash, backslash, drive prefix, `.`/`..`/empty segment, query/fragment, percent escapes or NUL; only `[A-Za-z0-9._/-]` and exact lowercase `.png` or `.jpg` suffixes are allowed. Length limit 240 ASCII characters. No SVG, GIF, WEBP, PDF, data URI or URL. Canonicalize the selected project root, then every existing parent and final asset; reject any symlink component (including the final file), any non-regular file, and any path escaping the canonical root. Missing/unreadable file, unsupported format, oversize or malformed payload is an `AMX6001` at the logo field (decode/engine failure after validation is `AMX6002`). Reject instead of silently omitting the brand: HTML preview/run remains in a failed state; exports do not replace an existing destination. Size limit 256 KiB encoded file; decoded dimensions 1-1024 pixels per axis, at most 1,048,576 pixels total; verify MIME by decoded signature and dimensions, not suffix alone; reject animated/multiframe input. No EXIF location/metadata or original filename is embedded in reports; decode and re-encode a single image frame into bounded PNG bytes (at most 1 MiB) in the trusted process. If conversion exceeds the bound, fail before writing. No fallback network lookup or path in HTML/OOXML.

HTML embeds the sanitized PNG as an inline `data:image/png;base64` image; PDF uses its local engine image API with the same PNG bytes; DOCX embeds the PNG as package media with alt/description where supported by the generator, and must expose adjacent `logoAlt` text if embedded image alternatives cannot be verified. No standalone external image path remains in output. Image display is bounded to 160 CSS px wide / 48 CSS px high (or physical equivalents preserving aspect ratio), never upscaled beyond intrinsic size. If an adapter cannot embed the validated asset within its limit, its export fails `AMX6002` and preserves the existing destination; other formats do not silently substitute a different logo. Offline operation requires no remote fonts/styles/images/scripts; use bundled, licensed local font assets or installed fallbacks with measured legibility, retaining required redistribution notices. Do not promise identical font metrics or tagged PDF/Office support.

Accent is only an accent: use on large marks/rules or on text/controls when contrast against the actual background is at least 4.5:1 for normal text and 3:1 for large text and essential UI boundaries. Compute WCAG relative luminance from the six RGB channels. A syntactically valid accent with inadequate contrast is **not** rejected; use neutral dark text and a neutral high-contrast focus/border for those roles, preserve the configured color only for nonessential decoration where distinguishable. Never recolor chart series, source syntax or user-provided content to enforce branding. The fallback and effective color usage are deterministic and recorded in UI preview; HTML/print/PDF/DOCX must retain labels and noncolor cues. No formal WCAG certification is claimed.

## 4. Shared Visual and Accessibility Rules

Tokens are normative intent with format-native implementations: light paper `#FFFFFF`, workbench surface `#F5F7F7`, borders `#C5CDCF`, primary ink `#18282D`, secondary ink `#405459`, focus `#075A82`, error `#A52626`, success `#166534`, neutral accent `#146C94`. Test contrast against the actual drawn surface; when a token falls below 4.5:1 for normal text or 3:1 for essential non-text boundaries, substitute primary ink/focus as appropriate. Never use color alone for status. Type: locally available sans UI/report body with serif-free fallback; monospaced source, body 14-16 px desktop, 16 px HTML, 10-11 pt print, headings 1.25/1.5/2 times body with semantic H1/H2/H3; line height >= 1.4 for prose. Spacing grid 4/8/12/16/24/32 px (print 1 px ~ 0.75 pt), compact lists may use 4, controls minimum 32 px target with 44 px touch target on narrow HTML. Long unbroken data wraps without overlapping. Use licensed bundled export fonts; no remote font fetch.

Hierarchy: document title (existing frontmatter `title` or neutral title), publisher/logo and author/status/classification line, narrative in source order, source fences and shown views at their original positions, optional footer/legal notice. HTML uses semantic header/main/footer, real headings, table captions/headers, figure captions/descriptions and visible source `<pre><code>`; its filter/sort/page controls remain keyboard operable and its static print table/plot data remains original order. PDF uses searchable headings/body/table/source text, page numbers and textual chart data; tagging is not asserted. DOCX uses editable heading/paragraph/list/table/source structure and textual chart data; chart/logo images do not replace that text. Repeat table headers when available. Logo `alt` may be empty only when no logo is configured; effective logo requires descriptive `logoAlt`. Escape all metadata, labels and URL-like content as plain text in each format. Empty data has `No rows` / `No data` text, not fabricated results.

Commands use familiar icon plus visible text on first-use/primary actions; icon-only commands require a tooltip and accessible name. Meaningful disabled commands state the reason. Keyboard order follows visual order; focus is not trapped by panels or preview, Escape closes transient UI and restores the invoker, dialogs return focus on dismissal. Visible 2 px focus ring must survive browser zoom 200% and high-contrast modes; no shortcut may shadow platform text-editing shortcuts when an editor has focus. `aria-live`/equivalent announces start, success/failure and result counts once, without dumping data or private paths. Loading reserves dimensions and exposes a cancel/close affordance where safe; empty shows a relevant next command; failure shows a source-located message and retry; success identifies the completed action and current revision. Reduced-motion preference disables nonessential animation. Desktop supports 1280x720 and 800x600 minimum window sizes with no overlapping or unreachable primary commands; at 800x600 collapse secondary panels into tabs/drawers rather than shrink editor or preview to zero. HTML works at 360 px and 1280 px and in print without horizontal page overflow (wide tables may scroll on screen, wrap in print). PDF A4/18 mm and DOCX use their native flow, page break and pagination behavior; not pixel parity.

## 5. Desktop Ownership and State

The main process owns native open-project/open-file/save-as/export-destination dialogs; dialog results are intents, not trusted paths. Validate canonical root, existing parent, exact lowercase extension, symlinks, regular-file status, conflicts, destination atomic-write rules and buffer size after each selection. Cancel changes nothing. The webview cannot call filesystem, module/input loader, evaluator, process/shell or export adapters, or receive opaque file handles; it requests bounded typed operations, receives redacted diagnostics and display summaries, and renders sandboxed HTML preview. Never add a webview-side asset fetch. Existing `openProject`, `openDocument`, `updateBuffer`, `saveDocument`, `analyzeBuffer`, `runBuffer`, `previewBuffer`, `saveHtml`, `exportPdf`, `exportDocx` remain trusted main-process entry points; new dialog/session/tab operations must be typed and validated there.

Explorer recursively presents canonical contained regular `.amx` files in path order, grouped by relative directory; ignore dot directories, `.openamx`, `node_modules`, generated/build/artifact directories, symlinks, and generated `.html`/`.pdf`/`.docx` outputs. Search is case-insensitive substring on relative display path, never queries arbitrary disk; if nothing matches show `No matching files`. Explicit open of a hidden/ignored or outside-root file fails, not bypasses listing policy. Opening a module changes active tab but not the designated entry. Tabs are keyed by canonical file URI; one entry tab is explicitly designated for run/preview/export, with a visible entry badge and a command to designate an eligible contained `.amx` tab. Active tab controls edit/format/diagnostics; run/preview/export always use the entry tab's current unsaved text and its file-backed URI. If active differs from entry, label the operation with the entry file; never silently run the active module. Imported modules use the existing canonical entry-directory containment and saved dependency content; dirty non-entry dependencies must be saved or operation fails with a named unsaved-dependency prompt, not use stale disk silently. An untitled tab may be analyzed/formatted but cannot become entry for rooted operations until explicitly saved under the project.

Each tab has text, last observed disk hash, dirty flag, conflict flag and an incrementing edit revision. Switching retains all state. Save compares disk hash and refuses overwrite on mismatch; conflict offers compare/reload/discard or keep editing, never force-save automatically. Reload requires confirmation when dirty, rereads a contained regular file and replaces text/hash only on confirmation. Closing a dirty/conflicted tab, closing project, or quitting offers Save, Discard, Cancel (save failure/cancel keeps the tab/project open); entry closure requires choosing another entry or disables report operations. External changes set conflict on the affected tab; no silent overwrite, including after session restore. Recent projects/session data are machine-local (not `.openamx/project.json`), store at most 10 canonical roots and optional active/entry relative paths and panel sizes, never text, input mappings, evaluated values, HTML, diagnostics or local config contents. Restore paths only after validating existence/containment; never restore unsaved text or auto-run. Clear-recents/session command deletes local history; private paths are not logged or synced.

Resizable explorer/editor/preview/diagnostics/results/export regions have bounded minimums and keyboard resize alternatives (toggle/focus panel); collapse is reversible, layout persisted locally only. Focused editor and focused preview modes preserve tab, selection and scroll when exiting. Command palette searches named commands, displays shortcut and disabled reason; invocation uses the same typed operation as its toolbar equivalent. Minimum shortcuts: Ctrl/Cmd+O open project/file chooser, Ctrl/Cmd+S save active tab, Ctrl/Cmd+Shift+P palette, Ctrl/Cmd+Shift+F project search, Ctrl/Cmd+Enter run entry, Ctrl/Cmd+Shift+Enter preview entry, Escape close transient/focus mode; platform-specific collisions and editor text-edit commands take precedence. Export requires an explicit dialog/command, never a keyboard sequence that silently overwrites.

Editor minimum (Sprint 030): a proven maintained component with AMX fenced syntax highlighting, line numbers, bracket pairing, find/replace, undo/redo, multi-line selection, IME input, accessible label, 200% zoom and reduced-motion/keyboard/screen-reader proof on supported hosts. Canonical formatting only changes executable AMX fences; preserve cursor/selection using source offsets or restore nearest mapped boundary, preserve scroll, and support undo. Completion comes from pure source-ordered parser/checker/link facts, not evaluation. Static diagnostics show code/severity/file/original one-based UTF-16 line/column and navigate to the right tab/selection; runtime/input errors remain distinguishable. Navigating a dependency never replaces dirty text. Sprint 030 must document component license, Bun/Vue bundle size, IME, screen reader, focus/selection, keyboard, large-file and direct build/host compatibility; if proof fails, selection is blocked for Lead Developer review, not replaced with a custom grammar engine.

For every tab revision and input/config revision, invalidate prior run/preview/export success immediately; issue monotonically increasing request IDs bound to canonical entry URI, buffer revision, input revision and project generation. Only the matching latest request may commit UI results; late results are ignored even if successful. Start announces running, failure clears prior success/preview and keeps a labeled last-success artifact only if explicitly separated as stale; success reports the current revision. A failed or superseded export never reports current success. Do not claim cancellation stops main-process work; navigation/close may ignore a reply but cannot weaken destination checks or writes. Save and export failures preserve existing-destination no-write guarantees.

## 6. VS Code Direct Providers and CLI

Sprint 033 runs direct providers in the Node extension host using pure `parseDocumentText`, checker and read-only local module analysis. Current unsaved document text is authoritative for the entry; dependencies use an open unsaved VS Code document when available, otherwise a canonically contained local `.amx` disk file. No LSP, runtime evaluation, input CSV/JSON loading, CLI spawning or arbitrary writes. Locations are original-document zero-based VS Code UTF-16 ranges converted from core one-based UTF-16 coordinates; never point into normalized formatted text or Markdown prose. Only executable `amx` fences supply symbols. On parse/check/link failure, offer only independently proven local facts; ambiguous or unavailable targets produce no result plus existing localized diagnostics, not a guessed match.

| Provider | Required facts and result | Unsupported/withheld |
| --- | --- | --- |
| Hover | resolved local declaration kind/type and source signature, pure static type of binding/field/view and explicit imported origin; escaped Markdown plaintext | computed value, inferred runtime data, ambiguous/unknown name |
| Definition | declaration token range for preceding in-scope binding/type/function/view, or explicitly imported exported declaration in contained module | standard library without source, unresolved/cyclic/outside import, prose or non-executable fence |
| Symbols | ordered top-level declared types/functions/inputs/bindings/views with source ranges and meaningful selection ranges; nested record fields as children where located | synthesized values and anonymous expression nodes |
| References | exact resolved symbol identity across entry and read-only reachable contained modules, declaration optionally included by provider API convention; same-name shadowed tokens excluded | unresolved imports, dynamic text/interpolation without proven token identity, unrelated workspace files |
| Code actions | only range-checked parser/static diagnostic fixes with deterministic edit (e.g. missing exact `show` name when exactly one visible candidate), previewed workspace edit and revision guard; no auto-apply on save | speculative rename, data-dependent fixes, code execution, dependency writes without explicit confirmation |

An untitled document with imports has an import-unavailable diagnostic and no imported navigation; local-only symbols still work. Closed/changed dependencies invalidate cached results. Verify range and symbol identity with unsaved entry and dependency edits, cycles, duplicate names, multiline fences, and UTF-16 surrogate pairs. Existing formatting/completion/diagnostics remain; a first-error checker does not imply comprehensive diagnostics.

Sprint 034 CLI help must list actual implemented `run`, `render`, `export pdf`, `export docx` commands and exact options, show a local `.openamx/project.json` identity and frontmatter example only when supported, and point to a complete runnable example. Errors identify code, source location or JSON pointer, cause, and actionable next step without echoing secrets/private paths; exit nonzero on failures and retain existing no-write barriers. No interactive prompts. Onboarding distinguishes locally verified V0.4/V0.5 features from unverified native macOS 14+, Windows 11+, native Ubuntu 24.04+, Hutch package/launch, Office round trips, and project license/Marketplace publication. Local VSIX verification is not publication; WSL2 is not native Ubuntu proof. Sprint 034 documents only checks actually executed and obtains Lead Developer visual sign-off separately from automated regressions.
