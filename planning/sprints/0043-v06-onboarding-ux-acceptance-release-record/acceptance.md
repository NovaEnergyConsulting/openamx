# Sprint 043 Acceptance Criteria

Sprint 043 is complete when:

- The guided first-project workflow, starter examples, searchable bundled help, contextual links/tooltips, keyboard-shortcut reference, preferences, release notes, and bounded diagnostic-log export are implemented and verified. Log export omits private paths, input contents, source/recovery text, and credentials.
- V0.5 recent/session migration detects obsolete designated-entry state, preserves safe active tabs/layout where possible, removes obsolete entry selection, never auto-runs AMX, and has focused tests for valid, stale, malformed, and recovery-related session data.
- Integrated acceptance uses an isolated reproducible fixture covering project creation, multiple unsaved imports, logical inputs, project/external data editing, settings precedence, editor intelligence/refactoring, live preview, cancellation, HTML/PDF/DOCX/JSON/CSV export, conflicts, trash, and crash recovery.
- Cross-feature tests prove active-document identity and stale-job rejection across module/data/settings/project changes, no partial config or output writes, external path/content privacy, conflict-safe autosave, atomic rename/import changes, recovery without automatic source overwrite, and compatibility with V0.2-V0.5 language/CLI/report/data/VS Code behavior.
- The 100,000-row CSV and JSON data-editor experience is measured on the documented host with exact hardware/OS/runtime, fixture size, viewport/scroll/edit/history/cancellation outcomes, memory method, long tasks, commands, and artifacts. There is no fixed 3-second first-viewport or 100-ms grid-task acceptance ceiling. The observed interaction is explicitly accepted by the Lead Developer as usable; data integrity, full-range access, core editing/history, cancellation behavior, bounded fallback, and no silent truncation remain required.
- Sprint 041's earlier timing exception is dispositioned under the approved 2026-10-03 contract adjustment, not recorded as having met the superseded numerical threshold. Any changed implementation must be remeasured and reported; the accepted timing policy does not waive measurements or behavior criteria.
- Other performance budgets remain independently verified or explicitly dispositioned: 100-file project listing, live-preview debounce, supported cancellation acknowledgement/cleanup, and background analysis/validation/export responsiveness. The 100k grid timing relaxation does not apply to these workflows.
- Deterministic component/browser and available-host manual visual review covers contract screens/states at 1024x720 and a larger viewport, system/light/dark, keyboard/focus, contrast, drawers/dialogs, density, errors, cancellation, onboarding/help, and absence of dead/misleading controls. Evidence names the actual host/browser/OS/version. Browser or WSL2 results are not called native target certification.
- Root/desktop/extension docs and metadata are updated only to verified product behavior; stale prototype/spike/entry/manual-path instructions are corrected, historical V0.2-V0.5 specifications remain historical, and V0.6 version alignment occurs only after feature verification.
- Required root build/full tests, desktop direct RPC/unit/component/browser/typecheck/Vite checks, applicable extension compile/host regressions, performance fixtures, and `git diff --check` are run and recorded with exact commands, tool/OS versions, counts, warnings, bundle/performance results, artifacts/hashes/screenshots, and unavailable checks.
- `planning/state.md`, `planning/decisions.md`, `planning/questions.md`, and the Sprint 043 evidence record contain the integrated acceptance ledger and explicit Lead Developer disposition. Each residual has an owner, status, next action, and review point.
- V0.6 feature acceptance is reported separately from native macOS/Windows/native Ubuntu, Hutch packaging/launch, broad Office, project license/Marketplace, Sprint 033 apply-time action safety, V0.5 report-mobile overflow, and formal accessibility certification. None is marked passed without direct evidence or an explicit approved exception.
- Final status is `COMPLETE`, `COMPLETE WITH RECORDED EXCEPTIONS`, or `BLOCKED`. No release-ready, native-certified, Office-certified, Marketplace-published, or formally accessibility-certified claim is inferred from feature acceptance.
