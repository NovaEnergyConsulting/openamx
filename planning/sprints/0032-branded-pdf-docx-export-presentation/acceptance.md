# Sprint 032 Acceptance Criteria

Sprint 032 is complete when:

- Sprint 031's accepted shared resolved report model, strict project/frontmatter validation and sanitized logo asset preparation are in place with recorded evidence, or the Lead Developer has explicitly dispositioned the dependency with named prerequisite remediation completed before final PDF/DOCX exports. A user report of Builder completion alone is not a passed gate.
- PDF and DOCX consume the same resolved identity and immutable narrative/source/view sequence as HTML, using a single evaluated document and final narrative environment. No adapter re-parses configuration, reads input/module/logo paths, reevaluates AMX, or silently accepts invalid raw `report` fields or `data:` logos.
- Both formats present title, organization/author/status/classification/footer and approved local logo with safe alt/description, contrast-aware native styles, readable hierarchy, captions, tables, code/source and static charts with textual alternatives. PDF remains searchable; DOCX retains editable headings/paragraphs/lists/tables. Source defaults visible and explicit `sourceVisible: false` hides only formatted listing, not narrative/views/data.
- PDF page size/margins, page breaks, repeated table headers/page numbers and DOCX native page flow/section headers/footers are checked structurally. Original narrative/source/view/show order, declaration-order rows, four V0.4 chart kinds, null/empty data and snapshots are unchanged. No interactive or pixel-parity claim is made.
- Valid PNG/JPEG project logo is embedded only as the bounded sanitized PNG; invalid/missing/unreadable/traversal/symlink/mislabeled/oversize assets fail with location and no-write preservation. No external report media relationships, data URI bypass, remote requests, unlicensed fonts, silent brand omission or private input paths enter generated output.
- CLI `export pdf|docx --project-root`, no-option CLI behavior and desktop current entry buffer/selected project integration follow the accepted Sprint 031 identity root rules. Invalid config/assets/analysis/destination or serialization failure preserves existing destinations under the established atomic-write workflow; failed/superseded export is not shown as current success.
- Focused PDF/DOCX content/structure/path/no-write, CLI and desktop tests pass for identity precedence, metadata escaping, contrast/source visibility, page/table/chart order and pre-rename failures. Root `bun run build`/`bun test`, relevant desktop checks and `git diff --check` pass; exact commands/counts, font/license evidence and unavailable native viewers/Office checks are recorded.
- Format-specific limitations and representative output observations are handed to Sprint 034 for separate Lead Developer visual sign-off. Sprint 029 native workflow and Sprint 030 editor exceptions and inherited V0.4 platform/Hutch, broad Office and license/Marketplace residuals remain independently tracked, not reported as closed by PDF/DOCX tests.
