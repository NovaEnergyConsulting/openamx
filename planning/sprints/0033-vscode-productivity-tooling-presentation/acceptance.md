# Sprint 033 Acceptance Criteria

Sprint 033 is complete when:

- Hover, definition, document symbols, references and safe code actions are registered as direct Node-host providers, use pure parse/check/link facts and work only on exact executable `amx` fences. Narrative, bare declarations and ordinary fences remain inert; no LSP server, runtime evaluation, CSV/JSON loads, CLI spawn or arbitrary write is introduced.
- Hover presents escaped resolved declaration kind/type/signature and explicit imported origin where proven, without runtime values. Definition navigates to the correct original declaration token for preceding local or explicitly exported contained imported symbols; standard library without source, unresolved/cyclic/outside imports and ambiguous tokens return no fabricated result.
- Outline lists located top-level types/functions/inputs/bindings/views in source order with meaningful ranges/selection ranges and nested record fields where available. References use resolved symbol identity across only reachable contained modules, obey include-declaration, exclude shadowed same-name tokens and unrelated files, and withhold unproven interpolation/dynamic text.
- Code actions return only diagnostic-grounded deterministic edits with valid ranges and document revision/version guard, shown as previewable `WorkspaceEdit`; edits are never auto-applied on save. No speculative rename, runtime/data-dependent suggestion or unconfirmed dependency write is emitted; no action is preferable to an unproven fix.
- Open unsaved entry and dependency documents take precedence over saved disk versions in analysis; changed/closed dependency state refreshes relevant facts and diagnostics. Untitled buffers report import-unavailable without disabling proven local symbols. Parser/checker/link failure preserves independently proven facts but never guesses symbols or targets.
- Original-document one-based UTF-16 source coordinates map to exact zero-based VS Code ranges for CRLF, multiline fences, surrogate pairs, record fields and imports. Existing executable-fence formatting, source-order completion, static/link diagnostics and refresh/clear lifecycle remain green for V0.2-V0.4 cases.
- Extension Development Host tests exercise each provider, unsaved entry/dependency changes, explicit exports, cycles/containment, shadowing, stale results, diagnostic clearing and existing regressions. Extension `bun run compile` and `bun run test` pass; root `bun run build`/`bun test` pass if shared code is touched. Local VSIX package/install/installed-host checks are run where supported, with exact commands/test counts/artifact/version and unavailable conditions recorded. `git diff --check` passes.
- Extension description/onboarding reflects only proven functionality. Planning records distinguish Sprint 033 acceptance from Sprint 029/030 desktop exceptions, Sprint 032 manual viewer/visual review, native/Hutch/Office release checks and unresolved project license/Marketplace publication; a local VSIX is not publication.
