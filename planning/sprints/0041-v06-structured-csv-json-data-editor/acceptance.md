# Sprint 041 Acceptance Criteria

Sprint 041 is complete when:

- A maintained Vue-compatible CSV grid and JSON tree/editor candidate is selected only after a pinned proof records license, dependency versions, Bun/Vite compatibility, keyboard/IME/editing, raw/structured synchronization, undo/redo, bundle/memory impact, cancellation, and 100,000-row behavior. A failed proof leaves the candidate gate blocked and does not authorize hand-rolled virtualization.
- CSV supports virtualized editable cells/rows/columns, format-safe insertion/deletion/reordering, search, non-destructive sort/filter views, undo/redo, validation, and raw-text mode. Sort/filter never mutates the authoritative source.
- JSON supports nested tree editing, array-of-records grid, raw-text mode, add/remove/reorder, supported lossless transitions, undo/redo, and validation. Malformed, irregular, unsupported, or too-large values receive an actionable raw/read-only/unavailable state rather than freeze or silent truncation.
- Raw source remains authoritative and exact invalid JSON/CSV text is preserved through edits, autosave, conflicts, restart/recovery, and mode transitions. Structured serialization is deterministic and only applied after valid, current, conflict-free preparation.
- Existing strict JSON duplicate-key behavior, RFC 4180 CSV quoting/newlines/headers/row widths, source/data diagnostics, declaration order, null/default/DateTime/type validation, and output serialization semantics remain unchanged. Focused root regressions pass.
- Active AMX mapping/schema supplies type-aware cells/nodes, required/default/null/DateTime information, source/data diagnostics, and navigation to data locations, input/type declarations, and Sprint 040 editor facts.
- Explicitly mapped external inputs can be opened through the bounded Sprint 039 route and are clearly labeled external/private. No general external browsing, raw private paths, input contents, or private metadata leaks through project/RPC/log/diagnostic state.
- Contained and explicitly opened external data use Sprint 038 atomic autosave and disk-conflict rules. Invalid text, cancellation, stale revisions, external changes, failed validation, and failed writes preserve the existing source/destination and buffers.
- Data operations carry active URI/project generation/document and input/settings revisions/job ID. Late/cancelled/superseded jobs cannot update a new tab/project, publish stale validation, or write an output. Resource cleanup is proven or explicitly bounded.
- Supported 100,000-row fixtures prove first usable viewport, scrolling, editing, validation, cancellation, memory, and responsiveness with exact hardware/OS/runtime, fixture size, commands, timings, and thresholds. Larger/unsupported fixtures demonstrate bounded fallback. Core parse timing is not substituted for UI viewport evidence.
- Focused data service/RPC/component/browser tests, root build/full tests, desktop direct/typecheck/Vite checks, candidate proof, and `git diff --check` are run and recorded with exact versions, dependency/license evidence, counts, bundle/memory measurements, warnings, artifacts, and unavailable host limitations.
- `planning/state.md`, `planning/decisions.md`, `planning/questions.md`, and Sprint 041 evidence record candidate selection, raw/structured contract, external privacy, conflict/cancellation, scale results, residuals, and Sprint 042 entry conditions. Final live preview/export is not claimed complete.
- Final status is `COMPLETE`, `COMPLETE WITH RECORDED EXCEPTIONS`, or `BLOCKED`; no native release, Office, licensing/Marketplace, or formal accessibility certification is inferred.
