# Sprint 034 Acceptance Criteria

Sprint 034 is complete when:

- A reproducible V0.5 end-to-end fixture/example and F0-F6 temporary review manifest are recorded with source/data/config/logo hashes, safe local asset provenance and commands. Automated tests prove final values, identity precedence, source visibility, source/view/narrative order, existing table/chart behavior, invalid identity/analysis/destination no-write and existing-output preservation across supported formats.
- CLI help, errors and examples accurately cover verified `run`, `render`, `export pdf`, `export docx`, input/validation options and `--project-root` identity behavior. `run` remains noninteractive and its mapping/path semantics are unchanged. Errors give codes/locations/next steps without secrets or private paths; no unsupported command/feature is documented.
- README, V0.5 contract references, desktop/VS Code docs, example guidance, version metadata and release instructions accurately distinguish shipped V0.5 behavior from V0.2-V0.4 historical contracts. They state local/offline logo/source visibility constraints, HTML/PDF/DOCX format-native limitations, direct-provider boundaries and local VSIX status without claiming Marketplace publication, project licensing, broad Office or native platform support.
- Root `bun run build` and `bun test`; focused CLI/example/report/no-write checks; desktop direct RPC/typecheck/Vite; extension compile/host/package/install/installed-artifact checks; and `git diff --check` are run where supported. Planning records exact commands, tool/OS versions, test/assertion counts, artifact paths/hashes, warnings, failures and unavailable checks. A skipped/blocked package/native/viewer check is not represented as passed.
- Lead Developer completes the approved visual-review evidence form for available F0-F6 desktop, HTML, PDF and DOCX states, recording screen/window/zoom, named browser/PDF/DOCX viewer and version, pass/exception/blocked outcome, observations, artifact/capture hash and remediation. The final visual decision is signed/dated as `Approved`, `Approved with recorded exceptions`, or `Rejected`; manual review does not replace automated tests.
- The Sprint 033 `WorkspaceEdit` limitation receives an explicit Lead Developer disposition: resolve-time guard accepted as a documented bounded exception, or a separately scoped guarded command/preview implementation is required. Sprint 034 does not call the code-action revision-safety criterion fully passed without that decision and matching evidence.
- Final records enumerate separate dispositions and owners for: Sprint 029 native project/save/close and accessibility; Sprint 030 editor/analysis/accessibility exceptions; Sprint 032 viewer/Office visual evidence; Sprint 033 code action; native macOS/Windows/native Ubuntu, Hutch package/native-launch, broad Office, project license and Marketplace. Only direct evidence or explicit approved exception changes a status.
- V0.5 feature status and inherited V0.4/release-engineering status are stated independently. A feature-complete claim is prohibited while an unapproved product acceptance blocker remains; release-ready/published claims are prohibited while target-platform, Hutch, Office, license or Marketplace gates remain open.
