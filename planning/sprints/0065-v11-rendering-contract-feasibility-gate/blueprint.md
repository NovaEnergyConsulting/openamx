# Sprint 065 Blueprint: V0.11 Rendering Contract and Feasibility Gate

## Approach

1. Read the V0.11 master plan, repository instructions, and current renderer/desktop ownership boundaries. Record the initial worktree and ensure probes cannot overwrite or mutate user artifacts. Use the supplied kitchen-sink PDF only as a read-only baseline.
2. Build a traceable Markdown behavior matrix for PDF, DOCX, standalone HTML, and desktop preview. For each construct, record source fixture, expected normalized narrative structure, destination representation, actual result, evidence location, and unresolved owner. Keep narrative, executable AMX source, emitted views, and captured report items distinct.
3. Write the exact prose/code/raw-HTML/page-break contract. Cover LF and CRLF, blank lines, hard breaks, headings/lists/table cells, nested formatting, tabs/spaces in code, and escaping of interpolation results. Establish deterministic heading IDs/bookmarks, duplicate rules, and missing internal-target behavior.
4. Probe only the smallest shared, destination-neutral narrative representation needed to establish feasibility. Use installed `marked` where appropriate, but never render authored raw HTML. Demonstrate that escaped/interpolated values and emitted table cells remain text, not recursively parsed Markdown. No production adapter or dependency change is permitted.
5. Exercise image and link preparation in a disposable harness. Resolve author paths relative to the source document and canonicalize both file and permitted project/document root; test containment, symlinks, traversal, extension/content mismatch, invalid bytes, missing assets, percent encoding, and boundary-sized assets. Sanitize/decode supported PNG/JPEG and measure proportional fit without upscaling. Select proposed byte/pixel/output bounds from evidence and existing worker constraints, then request approval; do not use logo-specific limits by assumption.
6. Verify portable local links from final output locations. Generate temporary PDF/DOCX destinations, atomically relocate them, and verify authored relative targets still resolve from the final output directory. Check URI encoding and report exact viewer/Word behavior and prompts. Never introduce absolute local paths or copy companion assets.
7. Inspect the installed `docx/charts` API and create disposable package-level probes for all four chart kinds. Verify serialization, relationship targets, workbook embedding, cached values, data series/categories, axes, grouping, units, DateTime/numeric value semantics, null gaps, duplicate/order preservation, and empty/all-null truthful states. Confirm the probe bundle and actual desktop worker/package dependency resolution without editing production manifests.
8. Pilot the resulting native charts in actual Word desktop: open without repair warnings, inspect each representative kind, edit chart data/series, save, close/reopen, and confirm the change persists. Pilot Word web display and save/download, then inspect that the chart remains a native object in desktop Word. Record exact Word channel/version, OS, review date, files, and steps. If the user/reviewer or application is unavailable, mark this mandatory gate blocked; XML inspection is not a substitute.
9. Compare native chart results to shared chart-model meaning rather than ECharts option shape. Include numeric/UTC DateTime line axes, uneven x intervals, duplicate labels and source order, different units/axes, negative/zero, null gaps, empty/all-null states, scatter group order, and data-table alternative. If the native API changes axis meaning, grouping, order, or units for any accepted case, stop for Lead Developer decision; do not invent coercion or a static image path.
10. Specify a desktop navigation protocol without implementing it: only a real click in the active isolated preview may submit an opaque target ID plus unforgeable/current frame-revision context; the host maps the ID from its own prepared target table, rechecks scheme/path/type and active revision, obtains confirmation for external/local navigation, and invokes only the approved native action. Reject raw URLs/paths, authored RPC commands, stale or synthetic requests, traversal, symlinks, executable targets, and arbitrary message origins. Keep `allow-scripts` only, without same-origin or broad bridge capability.
11. Complete decision, risk, and acceptance matrices; update `planning/state.md`, `planning/decisions.md`, and `planning/questions.md` with proposal/evidence status only. Submit exact commands, temporary artifact locations, versions, and residuals. Ask the Lead Developer for an explicit disposition; Sprint 066 remains blocked until that disposition.

## Builder Contract Proposal

This section is a Builder proposal, not an approved product decision. The master plan remains authoritative; Lead Developer disposition is required before Sprint 066.

- Normalize CRLF and LF to logical LF before block/inline parsing. Every prose source newline becomes one visible break, including a soft newline; blank lines delimit paragraphs. Markdown two-space and backslash hard-break markers produce the same single break. A blank line must not produce an extra visible empty line.
- Preserve code block contents as literal text with tabs, spaces, and logical line breaks intact. Normalize CRLF line endings to LF but do not trim code lines or expand tabs. Apply equivalent whitespace-preserving code styling in all four destinations.
- Parse Markdown structure once into a destination-neutral representation. Resolve interpolation in text nodes only, escaping its result for the destination; never reparse it as Markdown or raw HTML. View-emission cells remain typed captured data rendered as text.
- Treat authored raw HTML as escaped literal text in every destination. Do not allow HTML tags, event attributes, resource references, SVG, or comments to become active. Recognize the exact standalone `<!-- page-break -->` only outside code; map it to PDF/DOCX page breaks and a print-only break in HTML/preview.
- Proposed heading fragments: normalize heading plain text to Unicode NFC; lowercase; retain letters, digits, `_` and `-`; replace whitespace runs with `-`; remove other punctuation; use `section` when empty; suffix later duplicates `-2`, `-3` in document order. The same fragment selects a logical target in all outputs; DOCX bookmark names map deterministically to valid Word bookmark identifiers. Missing fragments render without a hyperlink.
- Resolve asset and local-link author paths relative to the source document. Canonicalize the permitted project root when supplied, otherwise the canonical document directory; reject paths outside that root, any symlink component, missing/non-regular targets, and encoded traversal after decoding. Do not follow redirects or fetch remote resources.
- Proposed narrative image policy: PNG/JPEG by both extension and decoded content; one frame only; re-encode to strip metadata; require nonempty descriptive alt text; fit proportionally within destination content bounds without upscaling. Evidence supports a provisional 4 MiB source-byte limit and 4,000,000 decoded-pixel limit; cap sanitized output at 4 MiB per image and leave worker caps unchanged. A 4,000,000-pixel random JPEG at quality 100 was 11,677,897 bytes and would be rejected by the byte bound. The existing 8,000,000-character HTML and 32,000,000-byte binary limits remain the final aggregate limits; no cap change is proposed.
- For PDF, DOCX, and standalone HTML exports, calculate emitted relative local-file URIs from the final output directory, never the atomic temporary path; preserve companion-file relative layout and never copy companions. Encode URI path segments. For live preview, resolve against the active source document and dispatch only a host-owned opaque target ID.
- Proposed safe local-link extension allowlist for review: `.pdf`, `.png`, `.jpg`, `.jpeg`, `.txt`, `.csv`, and `.json`; exclude executable/application/script types. External links are HTTP/HTTPS only. Exact local types, viewer behavior, and host external-open API remain Lead Developer decisions.
- Preview protocol proposal: click handler inside the active isolated frame emits only `{kind, targetId, previewId, revision}`; the trusted handler sends only for `event.isTrusted` clicks on prepared links. The app verifies exact active iframe `contentWindow` and opaque origin, then sends typed RPC with the current active-document identity. Bun owns the current target table, maps the opaque ID, rechecks project/document generation, source revision, canonical path, symlinks, file type and allowed scheme, then asks for confirmation before a single approved native action. Reject raw URL/path fields, unknown IDs, stale/replayed IDs, wrong frame/origin, malformed messages, synthetic clicks, traversal, symlinks, executable targets, and non-HTTP(S) remote schemes. Clear the target table on revision, tab, project, or preview replacement. Retain `sandbox="allow-scripts"` without `allow-same-origin`; this is a proposal and changes no permission/RPC today.

## Builder Feasibility Findings (2026-10-09)

- Current Markdown behavior was exercised in-memory with paired LF/CRLF fixtures, duplicate headings, soft/hard breaks, tab/space-sensitive code, raw `<strong>`/`<script>`, a page-break comment, and an interpolated value containing `**` and HTML. LF/CRLF output matched. Current HTML behavior contradicts the required inert/interpolation contract as detailed in the matrix.
- `docx@9.8.1` exposes `docx/charts` (`ChartRun`, `ChartDataPatch`). A disposable Bun probe serialized bar, column, line, DateTime line, scatter, and all-null line chart parts with embedded `.xlsx` workbooks. Chart relationships were package relationships, with no external workbook relationship or macro part in the Word-web pilot download.
- The chart package supports category line axes; numeric categories serialized as `c:catAx` and Word web showed `10, 30, 30, 11` equally spaced. The UTC DateTime line serialized as `c:dateAx` with Excel date serials and source order. This cannot represent the accepted continuous numeric line meaning without changing semantics, so this is a failed feasibility gate requiring Lead Developer direction.
- `ChartRun` permits only primary/secondary value-axis assignment; a shared model with more than two independently mapped value axes has no faithful mapping established. Bar defaults place the first category at the bottom per package docs; `reverseOrder` is available but its Word behavior was not piloted. Scatter rejects null coordinates; the shared model's existing behavior (omit null-coordinate points from plot while retaining all source rows in the independent data table) is feasible as an adapter proposal. Empty scatter point series are rejected; an all-null line serializes without fabricated points.
- Actual Word web loaded the disposable document, showed chart elements, autosaved it online, and returned a downloaded DOCX retaining six chart parts and six embedded workbooks. A Word page-2 screenshot directly showed equal-spaced numeric categories. The UI's formal Word channel/build was not exposed; a taskpane resource error URL included `1.0.2610.6002`. The authenticated browser was Chromium 150.0.7871.250 on Linux x86_64 via VS Code 1.140.0 / Electron 43.7.3. This is Word web only; it does not prove desktop chart editing.
- No Microsoft Word desktop executable/application is installed on this Linux host. LibreOffice is installed but was not used as a substitute. Desktop open/edit/save/close/reopen is blocked; the web downloaded package's native parts do not satisfy that gate.
- A relative `./companions/asset%20one.csv` was serialized into PDF URI annotations and a DOCX external hyperlink relationship. Atomic outputs were relocated with companions and the relative target resolved from the new output directory; no absolute path or temporary residue was found. Chromium refused direct open of the relocated local PDF: `Forbidden. File does not reside within a trusted folder.` This is a viewer restriction, not a passing viewer check. Word local-link behavior was not tested.
- Generated PNG/JPEG samples and canonical-root checks proved rejection of traversal/out-of-root paths, symlink components, missing/invalid files, and extension/content mismatch. Portrait 1200x1800 JPEG: 2,160,000 px, 1,405,065 bytes, 1,042,990 sanitized bytes. Landscape 2400x1350 JPEG: 3,240,000 px, 2,127,558 bytes, 1,581,471 sanitized bytes. A 2000x2000 JPEG decoded at the 4,000,000-pixel limit; 2001x2000 was rejected by Sharp at the pixel limit. The provisional image bounds are proposals only.
- The supplied `examples/kitchen-sink.pdf` was never modified. Its SHA-256 is `9add5c76030f9d6248a8126efa0d96f2e1fc2168a654da1f07e2b6953e3be778`; `pdfinfo` reported 20 A4 pages, 149,296 bytes, unencrypted, no JavaScript. Page 1 was raster-captured at 80 DPI and visually inspected: current PDF output shows Markdown delimiters, code fences, and pipe-table syntax literally while retaining report identity, headings, footer, and pagination. Capture and inspection are both recorded, but only page 1 was visually inspected.
- No preview navigation implementation/adversarial runtime test was performed. Existing `App.vue` uses `sandbox="allow-scripts"`; current RPC has no navigation action. The protocol above is a proposal only.

## Native Chart Semantics Probe Matrix

| Chart case | Preserve from shared model | Reject as a feasibility result if |
|---|---|---|
| `bar` / `column` | Chart kind/orientation, source order, duplicate categories, series identity, signs and zero | Native object changes kind/orientation, merges/reorders categories, or loses series values |
| Numeric `line` | Continuous numeric x axis, uneven intervals, duplicate x, source order, null y gaps | Values become equally spaced categories, are sorted/aggregated, or null becomes zero |
| DateTime `line` | UTC time meaning, actual elapsed spacing, source order and null gaps | Timestamps are local-time shifted or categorical/equally spaced without approved decision |
| Mixed measurement units | Existing normalized data and independently meaningful axes/labels/units | Axes/series imply a common unit or values are converted/coerced without contract |
| `scatter` | Group first-seen order, numeric x/y meaning, duplicate coordinates and separate axis units | Groups collapse, coordinates/categories change meaning, or null coordinates become fabricated values |
| Empty/all-null/mixed null | No invented points/units; truthful title/description and complete table alternative | A success-looking chart invents points/values, null becomes zero, or a static image replaces editable native chart |

No alternative chart mapping is approved by a successful subset probe. A failed case is a decision item, not permission to narrow required scope.

## Desktop Navigation Protocol Proposal

- Prepared preview content assigns each permitted target an opaque, per-document identifier. Authored content never supplies the native URL/path or a privileged command to the host.
- Only a genuine user click handled within the active isolated frame can request navigation. The request includes exact frame identity and current document revision/nonce; synthetic, replayed, stale, and unbound messages are rejected.
- The host resolves the opaque ID through its own current prepared-target table, revalidates scheme, canonical path containment, symlink status, file type, and document revision, then applies confirmation before dispatching only an approved external HTTP/HTTPS or safe local-file action.
- Internal fragments stay within the preview and do not invoke host navigation. Remote resources/images are not fetched by report rendering. Local targets must be non-executable and in the accepted type allowlist from the gate.
- Preserve opaque-origin iframe isolation with `allow-scripts` and without `allow-same-origin`; no parent, bridge, direct filesystem, arbitrary RPC, or application path capability is granted to authored content.
- Exact message encoding, target identifier lifetime, allowed local file types, and confirmation presentation must be specified against existing RPC ownership and submitted for approval. This protocol is a proposal until Lead Developer disposition.
