# Sprint 031 Blueprint: Shared Report Identity, HTML Presentation, and Branding

## Approach

1. Inventory the existing CLI and desktop report calls, document frontmatter locations, version-1 input configuration parser and HTML/PDF/DOCX traversal to preserve their loader/evaluation and no-write boundaries. Pin representative V0.2-V0.4 output values/source/view order/interaction before changing presentation; do not require identical historical HTML bytes after styling.
2. Add a trusted report preparation API that accepts the already evaluated document, final environment, immutable view emissions and an explicit optional project-root/identity context. Resolve metadata and final-environment narrative once into immutable ordered content and identity, then serialize HTML from that model. Provide a typed format-neutral contract for Sprint 032; keep compatibility entry points for existing callers without triggering another loader/input/evaluation pass.
3. Extend version-1 config parsing narrowly: `report` is optional only in project config, never local config. Parse structured JSON/YAML with duplicate-key detection and original source coordinates, validate field types/length/unknown keys, and report bounded `AMX6001` errors with RFC 6901 project pointers or original frontmatter UTF-16 line/column. Check project fields before applying frontmatter overrides; only absent fields inherit, `logoAlt` must accompany a new logo override. Keep historical top-level title and existing input mapping behavior intact.
4. Implement one trusted logo preparation path for CLI and desktop: canonical root and symlink-free components, exact lowercase format/size/dimensions/frame/signature limits, sanitized metadata-free PNG re-encode and byte cap. Supply only bytes, alt text and safe display size to adapters. Test nonexistent, unreadable, oversize, mislabeled, malformed, animated, traversal/symlink and rootless paths before rendering or writes; preserve neutral no-logo behavior. Resolve accent contrast separately from source/chart colors.
5. Thread the optional explicit CLI `--project-root` through `render` and `export pdf|docx` identity preparation without touching `run` or CLI input path bases; desktop passes the selected canonical root behind typed main-process RPC. Preserve HTML plus named-output write grouping and PDF/DOCX atomic writers. Where Sprint 032 presentation is not yet implemented, do not claim their identity rendering complete; any temporary adapter compatibility must not silently ignore invalid identity or assets.
6. Redesign standalone HTML with semantic title/header/main/footer, bounded inline logo, metadata hierarchy, escaped narrative/source/views, readable table/chart framing and original-order print rules. Reuse the existing view emission and interaction layer rather than changing captured data, sorting/filter/pagination logic or print alternatives. No network fonts/assets/scripts; check print and narrow responsive overflow.
7. Add focused shared config/asset/model tests and HTML/CLI/browser regressions in existing test files where suitable. Assert precedence/diagnostic locations, neutral default, visible and explicit hidden source, failure/no-write, deterministic fixed-input structure, script-safe escaping, four chart kinds and table interaction/static print order. Run root build/full tests, relevant desktop direct/RPC/typecheck/Vite checks for touched caller code, browser HTML checks and `git diff --check`; record actual commands/limits and Sprint 032 model handoff.
