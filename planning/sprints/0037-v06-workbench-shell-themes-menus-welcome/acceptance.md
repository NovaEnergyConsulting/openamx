# Sprint 037 Acceptance Criteria

Sprint 037 is complete when:

- `App.vue` no longer owns an unstructured monolithic workbench. Focused workbench, explorer, tabs, content panes, contextual pane, runtime drawer, command palette, welcome, status, and dialog components communicate through an explicit typed state/composables boundary.
- The workbench presents the approved explorer/source/context split with bounded draggable dividers, bottom/right runtime drawer docking, source-only and preview-only focus modes, persisted local layout, and adaptive behavior at 1024x720 and a larger desktop viewport.
- Active-document tabs and file-kind shells work for AMX, CSV, JSON, settings/configuration, external mapped data, and generated outputs. Switching active documents uses Sprint 036 identity/job state and cannot display a stale result as current.
- Crowded workflow/header strips, designated-entry controls, dead wide-window selectors, separate format buttons, and plus/minus pane controls are removed or replaced by functional commands. No visible control is a placeholder or misleadingly enabled.
- One typed command registry supplies native menu integration where available, command palette, shortcuts, and contextual actions. Every command has a stable ID, enabled/disabled predicate with reason, accessible name, and icon tooltip where needed. Browser tests prove keyboard invocation and focus restoration; native claims remain labeled unavailable without direct host evidence.
- System, light, and dark tokens cover workbench surfaces, CodeMirror, data shells, preview, drawers, dialogs, focus, status, contrast, and reduced motion. Status is not conveyed by color alone. Screenshots and checks cover dense, empty, loading, running, paused, stale, error, success, conflict, recovery, and cancellation shell states as applicable.
- Source/preview focus mode, palette, drawer, dialog, tab, and divider interactions preserve or restore focus, active document, selection, scroll, and layout state. Keyboard navigation and visible focus are tested.
- Welcome renders Open Project, Create Project routing hooks, validated recents, starter examples, guided-first-project entry, recovery/release-note indicators, help search entry, and concise empty/error states without inventing project lifecycle behavior scheduled for Sprint 038.
- Component/browser checks and deterministic screenshots prove populated/empty shell interaction, pane resize/docking, command enablement, keyboard focus/restoration, themes, reduced motion, and required viewport coverage. Browser/shim evidence is explicitly separated from native-host evidence.
- Existing Sprint 036 typed RPC/job/authority contracts remain green. No webview filesystem/process/evaluator/arbitrary-path/final-write authority is introduced. Any shell RPC additions are bounded and typed.
- Focused desktop tests, `bunx vue-tsc --noEmit`, direct `bunx vite build`, the desktop RPC contract check, and applicable root/VS Code regressions are run and recorded with exact versions/counts/warnings. Missing `.hutch/devkit` or unavailable native host checks are recorded as blocked/unavailable, not passed.
- `planning/state.md`, `planning/decisions.md`, `planning/questions.md`, and the Sprint 037 evidence record identify visual exceptions, bundle/performance impact, native residuals, and the explicit conditions for Sprint 038. Project lifecycle/autosave/trash/recovery are not claimed complete.
- Final status is `COMPLETE`, `COMPLETE WITH RECORDED EXCEPTIONS`, or `BLOCKED`; no native release, Hutch, Office, license/Marketplace, or formal accessibility claim is inferred.
