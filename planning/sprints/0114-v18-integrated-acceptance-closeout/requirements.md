## Accepted Product Contract

- Diagram bodies use ordered recursive primitive, `for`, and braced
  `if`/`else` content. Conditional-inside-loop and loop-inside-conditional
  nesting are supported; any nested `for` is rejected at parse time.
- Diagram controls are evaluated during model creation. Output is
  depth-first, source ordered, and fixed per model across frames; primitive
  properties evaluate with the requested timeline value and each generated
  instance's own loop bindings.
- `AMXD6001` rejects the diagram time variable in control expressions.
  `AMXD6004` rejects the 65th control-originating primitive at model
  creation. The cap is 64 control-originating emissions per diagram;
  direct top-level primitives do not consume it.
- `AMXD013` remains the separate 512-authored-primitive-declarations-per-
  report limit. Each authored primitive declaration counts once regardless
  of control repetition. No report-wide generated cap is added.
- Version 2 serialized models retain ordered expanded instances and bindings;
  version 1 no-control models remain readable. Unsupported/incomplete
  control-bearing payloads fail closed.
- Standalone HTML is interactive and starts at the lower time bound. PDF
  uses a static lower-bound SVG and DOCX a static lower-bound PNG. There is
  no separate static HTML diagram renderer.
- D111-02 remains an accepted potentially unbounded-work residual. The
  64-output cap does not bound loop iteration count, CPU time, or memory.
- Generated identities are internal only. Repeated authored primitive labels
  are not unique generated-instance identifiers or source-level references.

## Closeout Principle

S114 may recommend V0.18 integrated acceptance only within the recorded
evidence and separately dispositioned scope. Raw `FAIL`, `BLOCKED/UNAVAILABLE`,
and `NOT RUN` results remain unchanged even if the product owner accepts them
as named residuals. No release authority follows from S114 acceptance.
