# Sprint 114 Acceptance Criteria

Sprint 114 closes integrated V0.18 acceptance only after dependencies and
owner dispositions are reconciled, all required language and cross-surface
evidence is traceable, raw failures/unavailable checks remain accurate, and a
separate product-owner closeout disposition is recorded. S114 adds no product
behavior and authorizes no release.

## Entry and Scope

- S109-S111 dispositions and accepted contracts are verified against their
  evidence and lifecycle records.
- The S112 disposition conflict is resolved explicitly. S112 Builder
  evidence and global ledgers say owner disposition PENDING, while S113
  Builder evidence reports user acceptance with residuals. S113 evidence is
  not silently substituted for the missing canonical S112 disposition record.
- S113 ACCEPTED WITH RECORDED RESIDUALS and its raw root/VS Code/typecheck/
  desktop/native results are recorded accurately.
- Separate S114 execution authorization and exact verification/output plan
  are recorded before integrated checks run.
- Verification-only scope contains no source/test/spec/example correction.
  A discovered defect is referred for separate corrective authorization.

## Integrated Language and Runtime

- The full accepted source path parses, checks, formats, and evaluates
  recursive diagram content without source-order or location regression.
- Nested `for` remains parse-rejected; `AMXD6001`, `AMXD6004`, authored
  `AMXD013`, exact cap boundary 64/65, and per-diagram/control-only accounting
  are verified consistently.
- Expansion visits controls once during model creation, preserves order and
  membership per model, and evaluates each instance's properties with its
  loop binding plus requested `t` across lower/interior/upper frames.
- S112 version 2 serialized membership and supported bindings round-trip;
  v1 no-control models read; unsupported/incomplete payloads fail closed.
- Standalone browser output evaluates the actual embedded runtime and
  matches in-process frames. Mark the S112 Vite bridge/native/cross-platform
  results separately; do not infer host parity.
- PDF and DOCX contain the same lower-bound membership/order and expected
  properties with their accepted SVG/PNG representation and metadata.
- The Example 08 output is runnable, below the cap, fixed in membership over
  animation, and has animated `t`-dependent properties.

## Editor and Documentation

- Shared parser-proven facts, VS Code actual TextMate host scopes, and desktop
  CodeMirror presentation are verified as distinct surfaces.
- The additive V0.18 specification and README/example links match accepted
  S109-S112 contracts and S113 changes; no historical spec is rewritten.
- No source-addressable generated-instance identity or unique repeated
  primitive label is claimed.

## Verification and Residuals

- The approved focused root tests/build, VS Code host suite, desktop
  typecheck, and applicable desktop UI tests have exact outputs and statuses.
  Broader root tests run only if specifically approved.
- Resource/performance results identify host, workload, repetitions, sizes,
  and limitations. The 64-output cap is never described as an iteration,
  CPU, or memory bound.
- Preserve the HTML 1 MiB versus 100 MiB discrepancy; no broad output policy
  change is part of closeout.
- Existing S112/S113 failures, retries, skipped native checks, unrun
  platforms, Hutch no-result, and analyzer disagreement remain raw outcomes
  unless new direct evidence resolves them. Separate acceptance of residuals
  does not convert them to PASS.
- All rows in `integrated-evidence-matrix.md` have execution evidence or an
  explicit residual/NOT RUN/BLOCKED disposition and owner.
- Final changed-path/artifact audit and `git diff --check` pass for the
  approved evidence changes. No historical artifacts are overwritten.
- Builder recommendation and product-owner ACCEPTED/CLOSED or
  BLOCKED/OPEN disposition are distinct and recorded.
- Release, publication, package/version change, installer distribution, and
  platform certification remain separately unauthorized.
