# Sprint 029 Acceptance Criteria

Sprint 029 is complete when:

- Native main-process project/open-file/export destination dialogs drive the workbench with no typed path entry as the primary workflow. Cancel is a no-op; paths returned by dialogs receive canonical, root, symlink, regular-file, exact extension and destination/conflict validation. Existing destinations survive invalid analysis and pre-rename export failure.
- Explorer lists only ordered, contained regular `.amx` files, grouped by relative directory; dot/`.openamx`/`node_modules`/generated/build/artifact trees, symlinks and outputs are excluded. Case-insensitive relative-path search, empty/no-match states, active-file affordance and rejected hidden/outside explicit opens are verified.
- Two or more open tabs retain independent unsaved text, revisions, dirty/conflict flags and active state across switches. One eligible contained file-backed tab is designated entry; opening a module never silently changes entry. Active tab editing/save/format/analysis and entry-buffer run/preview/export are verified when active differs from entry, including unsaved entry content and saved local imports. Dirty dependency usage fails with a named save-first path, not a stale report.
- Save refuses a disk-hash conflict without overwrite. Dirty/conflicted tab close, reload, project change and quit use Save/Discard/Cancel; cancelled or failed saves retain text and tabs. Entry closure either selects an explicit new entry or disables report actions; external changes cannot be overwritten silently.
- Recent projects/session metadata are machine-local, bounded to ten roots, optionally restore safe relative active/entry and panel state, and can be cleared. Missing, moved or substituted paths fail safely. No unsaved text, private input paths, config contents, results, diagnostics or rendered HTML are persisted or auto-run on restore; no private session data enters shared project files or version control.
- Explorer/editor/preview/diagnostics/inputs/results/export layout resizes, collapses and restores predictably. Focused editor/preview modes retain tab/scroll/focus state; 1280x720 and 800x600 show reachable core commands and no overlapped UI, with reversible keyboard panel controls and visible focus.
- Palette and shortcuts cover opening projects/files, switching tabs, save, format, run, preview, project search and focused layout modes; exports have explicit dialog/command. Toolbar, palette and shortcuts invoke the same typed operations, disabled reasons are available, Escape restores focus and editor text-edit shortcuts retain precedence.
- Focused desktop tests prove dialog validation, session privacy, explorer containment, tab/entry/dirty/conflict/reload lifecycle, commands and keyboard/focus/layout state, stale responses and main-process-only authority. Existing root/desktop direct/RPC/typecheck/Vite checks remain green where supported; record exact commands, counts and unavailable package/native gates. `git diff --check` passes.
- Planning logs capture actual implementation/verification, any approved deviations and a clear Sprint 030 handoff. No full editor, report identity or VS Code provider feature is claimed; inherited V0.4 native platform/Hutch, Office and license/Marketplace residuals remain separate.
