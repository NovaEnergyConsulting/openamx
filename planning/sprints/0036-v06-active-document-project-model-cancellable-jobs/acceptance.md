# Sprint 036 Acceptance Criteria

Sprint 036 is complete when:

- Desktop operation state no longer depends on a designated entry. Typed active-document state and generalized document/tab records cover AMX, CSV, JSON, configuration/settings, external mapped data, and generated outputs without changing CLI entry-file semantics.
- Every desktop analysis/input/report/export job carries canonical active URI, project generation, document revision, input/settings revision, and monotonically increasing job ID. Tests prove only the matching current identity can publish progress completion, diagnostics, preview/result state, or export status.
- A project/tab switch, active-document switch, edit, input/settings change, supersession, cancellation, or project generation change invalidates prior work. Late and cancelled responses are discarded, resources are cleaned up, and no stale response writes an output.
- The contained source overlay is integrated through the existing loader boundary. Unsaved reachable AMX imports take precedence, unopened dependencies use canonical disk content, entry text behavior remains correct, and containment, explicit exports, cycle detection, source locations, evaluation order, and input-entry semantics remain intact.
- Focused root tests prove overlay precedence, saved fallback, outside-root rejection, bounded input, cycles, locations, and unchanged no-overlay CLI run/render behavior. Existing root module/input/output and example tests remain green or any unrelated baseline failure is explicitly recorded.
- A trusted desktop job manager and worker protocol supports preview/run, input loading/validation, and report preparation/serialization with typed start/progress/completion/failure/cancel/supersede messages, bounded payloads, private-path redaction, cleanup, and main-process-only destination validation and atomic writes.
- Real representative jobs prove cancellation or termination behavior at documented phases. Evidence records acknowledgement latency, cleanup/resource results, memory/payload measurements, and limitations. Cooperative-only or uninterruptible phases are explicitly identified and are not reported as fully cancellable.
- In-memory strict JSON/CSV parse and validation APIs expose the minimum schema/export metadata needed by the desktop without changing V0.3 data wire semantics, strict duplicate-key behavior, RFC 4180 parsing, diagnostic order/locations, input precedence, or runtime materialization. Focused valid/invalid/large-data tests pass.
- Typed RPC contracts and direct tests cover active-document identity, job lifecycle, cancellation/supersession, bounded/redacted payloads, stale responses, data validation/schema metadata, and no-write preservation after invalid, cancelled, stale, or failed work.
- The webview receives only bounded typed state and sandboxed preview data; tests or review show no webview filesystem, process, evaluator, loader, arbitrary-path, or final-write authority.
- Existing CLI behavior, unchanged VS Code behavior, root build/tests, focused desktop tests, and applicable type/Vite checks are run and recorded with exact commands, counts, versions, warnings, and unavailable-host limitations. Missing `.hutch/devkit` remains a blocked host check rather than a pass.
- `planning/state.md`, `planning/decisions.md`, `planning/questions.md`, and the Sprint 036 evidence record document implementation decisions, residual risks, measured budgets, and conditions for Sprint 037. Sprint 037 UI/project workflow work is not claimed complete.
- The final status is `COMPLETE`, `COMPLETE WITH RECORDED EXCEPTIONS`, or `BLOCKED`; native menu/dialog/window behavior, grid candidate/100k viewport selection, native release, Office, licensing, Marketplace, and formal accessibility gates remain separate unless directly proven by their owners.
