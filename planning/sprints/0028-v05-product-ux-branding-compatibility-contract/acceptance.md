# Sprint 028 Acceptance Criteria

Sprint 028 is complete when:

- An authoritative V0.5 contract exists and is linked from the planning record. Its versioned, additive project identity schema and report metadata specify exact keys/types, defaults, precedence, validation, source locations, diagnostics, fallback and migration behavior while preserving `.openamx/project.json` version-1 input mapping semantics.
- The contract specifies allowed local logo formats, size/dimension/path limits, canonical root containment and symlink handling, missing/unreadable/unsupported asset behavior, offline HTML/PDF/DOCX embedding limits, alt text and safe accent/contrast rules. No remote assets or machine-local secrets are required.
- V0.2-V0.4 documents without V0.5 metadata retain their language/data/view/export semantics, including visible formatted AMX source by default. A changed default is not accepted without explicit Lead Developer approval and migration guidance. The report presentation model preserves final narrative context, emission/source order, print/static chart alternatives, and no second evaluation.
- The visual-system contract has testable tokens/states for type, spacing, color, focus/keyboard, icon/command usage, accessible metadata/data alternatives and responsive desktop/report treatment, with HTML/PDF/DOCX format-native mappings and documented limits rather than pixel parity.
- Desktop contract defines native dialogs, containment-aware explorer, multi-file tab/entry/dirty/conflict/reload lifecycle, session privacy, resizable/focused layouts, palette/shortcuts, editor minimums, analysis/navigation, current-buffer run/preview/export states, bounded typed RPC and stale-response prevention without granting webview filesystem or execution authority.
- VS Code direct-provider contract defines hover, definitions, symbols, references and contextual actions, including exact sources/locations, unsaved text/local module behavior, unsupported cases and no LSP/runtime/data loading. CLI help/error/onboarding outcomes and honest residual release wording are defined.
- A Lead Developer visual-review checklist and representative fixture manifest cover desktop, HTML (desktop/mobile/print), PDF and DOCX, normal/error/fallback/accessibility states, evidence recording and Sprint 034 sign-off. Automated regression criteria remain separately required.
- `planning/state.md`, `planning/decisions.md`, and `planning/questions.md` record agreed choices, unresolved blockers, ownership of later work and the separate native platform/Hutch, Office, license/Marketplace residuals. Sprint 028 is marked prepared/delivered pending Lead Developer acceptance until approval is explicit.
- Documentation is checked for unresolved placeholders and internal contradictions; `git diff --check` passes. No production UI, parser/runtime, CLI, VS Code, report rendering, config, or export code is modified during this sprint.
