# Sprint 030 Acceptance Criteria

Sprint 030 is complete when:

- The dependency gate is recorded: Sprint 029 is explicitly accepted or has a documented Lead Developer disposition authorizing Sprint 030 implementation with the remaining Sprint 029 blockers still OPEN. Approval of Sprint 029's changes alone is not acceptance of its native picker/close/quit behavior. No Sprint 030 completion erases these residuals.
- A maintained editor component has a recorded package version/license, measured bundle impact and bounded proof of Bun/Vue/direct build and available host compatibility, keyboard/focus, IME composition, screen-reader label/navigation, undo/selection, 200% zoom, reduced motion, resize and large-file behavior. A failed proof is escalated before component adoption; no custom AMX grammar/editor engine is substituted.
- The textarea is replaced by an accessible code editor with executable `amx` fence highlighting, line numbers, bracket behavior, find/replace, undo/redo, multi-line selection, stable scroll/resize and per-tab selection. Markdown narrative and non-`amx` fences remain inert; switching tabs never loses dirty text.
- Canonical formatting changes executable fences only and preserves undo plus mapped selection/cursor (or documented nearest safe position) and scroll. Completion and static diagnostics reuse pure source-order parser/checker/local-link facts; editor assistance neither evaluates AMX nor loads CLI CSV/JSON inputs.
- Static diagnostics display severity/code/file/original one-based UTF-16 line/column and refresh/clear with current buffer revision. Navigation selects the correct contained tab and original source range, including unsaved local entry text, without replacing dirty dependency text; runtime/input errors are visibly distinct from static results. Multiline fences, CRLF and non-BMP characters are covered by focused cases.
- Input configuration, run, preview and HTML/PDF/DOCX export show explicit running/success/failure with current entry/revision identification. Edits, input changes, project/tab switching, late responses and failed runs cannot leave stale preview/results/export success presented as current. Result summaries remain bounded and private input paths are redacted; export invalid analysis/destination preserves existing outputs.
- Focused desktop editor/UI/RPC tests cover unsaved multi-tab behavior, formatting/navigation/diagnostics, imports, input/run/preview/export state transitions and keyboard/accessibility baseline. Run desktop direct RPC tests, direct Vue typecheck/Vite build, root build/tests and available native/package checks; record exact commands/results/limits and `git diff --check` pass.
- Planning logs state actual evidence, editor selection and license, accessibility/native limitations, Sprint 029 blocker status, and the Sprint 034 visual-review handoff. No V0.4 native-platform/Hutch, Office or Marketplace/license gate is claimed closed from WSL2 or a browser shim.
