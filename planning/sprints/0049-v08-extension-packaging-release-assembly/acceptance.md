# Sprint 049 Acceptance Criteria

Sprint 049 is complete when:

- Sprint 047 and Sprint 048 dependency dispositions are recorded and their finalized contracts are used without upgrading unverified remote target status.
- `release:extension` builds a VSIX from the existing esbuild/vsce workflow and validates root-authoritative stable version, extension identity, publisher `EngineersTools`, entrypoint, grammar/configuration resources, and package contents.
- The VSIX package is inspected independently of its filename. Its inclusion/exclusion rules exclude secrets, test output, unrelated source/build material and stale VSIX artifacts; package contents, size and SHA-256 are recorded. A platform-neutral single VSIX claim is made only if supported by the package/tool evidence.
- License and third-party notice requirements are checked against actual vsce/Marketplace/package behavior and authoritative supplied files. Accurate package metadata/references and required package contents are implemented where possible. No legal text or terms are invented. If full authoritative license/notices remain absent or unresolved, package-development tests may pass with fixtures, but `release:verify` and publication readiness accurately remain blocked.
- Extension documentation reflects the actual version/publisher, local package/install workflow, and manual-only Marketplace publication. It does not claim Marketplace readiness or published status without evidence.
- `release:collect <bundles>` validates each bundle's schema/version/full source commit, target/artifact records, completion marker, safe relative paths, file sizes and SHA-256 values before accepting it. It accepts only matching version/revision inputs, preserves sidecars unchanged, and rejects malformed, mixed, corrupt, missing, stale, traversal/symlink, duplicate, and conflicting data without changing prior accepted releases.
- Collection occurs in isolated fresh staging and promotes only after full validation to an absent versioned destination. Incomplete collection is not collectable/publishable. Existing releases are retained and never silently overwritten.
- `release:verify` is read-only and checks local manifest/assets/checksums, provenance, application identity, package/build status, target `available`/`missing`/`unverified`/`unsupported` state, recorded manual install/launch evidence, and licensing/notices readiness. It does not equate successful package/build checks with a native installation pass.
- `release:publish` is a separate explicit command defaulting to `NovaEnergyConsulting/openamx` with an explicit override. It validates authentication availability, source revision and version tag consistency before mutation; credentials never appear in logs/output/metadata.
- New GitHub Releases are staged as drafts where supported. Partial releases require explicit acknowledgement and clearly list requested missing/unverified/unsupported targets. An existing version tag is never moved; existing remote assets are verified identical or treated as conflicts, never silently replaced.
- Publication retry tests cover identical asset verification, later nonconflicting additions for the same version/revision, conflict rejection, interrupted upload, authentication failure, tag mismatch, and partial acknowledgement. All remote operations are mocked in automated tests; no test publishes a public release.
- Focused release and extension tests cover package inspection, license readiness, validation/security/error paths, collection atomicity, checksums/provenance, publication permissions, redaction, and retries. Applicable root, desktop, extension compile/package/host tests and `git diff --check` pass or have exact unavailable/failure results recorded.
- `planning/state.md`, `planning/decisions.md`, `planning/questions.md`, and Sprint 049 Builder evidence distinguish observed outputs, mock-only behavior, license readiness, native evidence, remote target status, and public publication status. Artifact hashes/sizes and exact commands are recorded.
- Marketplace submission remains manual. No public GitHub release, legal interpretation, six-target certification, signing/notarization, or Sprint 050 integrated repeat-release acceptance is claimed without its separate evidence/disposition.
