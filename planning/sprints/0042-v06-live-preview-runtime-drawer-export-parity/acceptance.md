# Sprint 042 Acceptance Criteria

> **Disposition: COMPLETE by explicit Lead Developer acceptance (2026-10-03).** The Lead Developer reports testing all Sprint 042 functionality and confirms that every requirement is met. The detailed Builder implementation and automated evidence remain in `builder-evidence.md`. This feature-sprint closeout does not imply native platform release certification, Hutch packaging acceptance, broad Office compatibility, or formal accessibility certification.

Sprint 042 is complete when:

- Active-document live analysis/preview is debounced and supports pause, resume, manual refresh, explicit power Run, progress, cancellation, and source-linked diagnostics. The active tab is the sole desktop analysis/preview/Run/export target; no designated-entry behavior returns.
- Preview executes the current active document and complete reachable unsaved contained module graph using Sprint 036 overlay semantics and the current settings/input revisions. Invalid edits preserve the last good preview with unmistakable stale/error state; stale output is never labeled current success.
- Switching AMX tabs, editing active/imported modules or mapped data, changing inputs/settings, pausing, cancelling, superseding, closing documents, or changing projects invalidates prior success. Only matching canonical URI, project generation, document revision, input/settings revision, and job ID may update state.
- Preview remains bounded and sandboxed. The webview receives only typed bounded state, redacted diagnostics, and sandboxed preview HTML; it has no filesystem, process, evaluator, loader, arbitrary path, native dialog, or write authority.
- The runtime drawer docks bottom/right and presents concise current operation state/progress plus expandable parser/static/input/runtime/export details. Static parser/checker/link diagnostics remain inline. Drawer navigation preserves source/data locations, keyboard focus, and active document.
- One unified Export workflow replaces separate format actions and supports standalone HTML, PDF, DOCX, and only eligible explicitly exported JSON/CSV values. Eligibility and formats are derived from current active-document analysis/schema, not guessed UI state. Multiple named outputs are supported where contractually eligible.
- Native Save selection and Open/Reveal operations occur only in trusted Bun services. Destinations inside or outside the project require explicit selection/consent, validated local shape, symlink/conflict checks, safe suggested names, overwrite confirmation, and private-path redaction. Native behavior is marked passed only after direct host observation.
- Every export completes analysis, input validation, report preparation, and serialization before the main process atomically replaces a destination. Invalid source/input/settings, stale identity, cancel at each phase, overwrite cancellation, unsupported format/path, conflict, serialization failure, and write failure preserve existing destination bytes. No partial output is visible.
- Successful export provides compact Open and Reveal actions without automatic launch; contained generated outputs refresh in the explorer with Open/Reveal/Delete actions. External/private destination paths do not enter shared project state or general RPC.
- Cancellation/supersession tests cover preview/run, input validation, report preparation, serialization, destination selection, overwrite and pre-commit phases. Evidence records acknowledgement, cleanup/resource closure, phase-specific limitations, and the non-interruptible atomic-rename boundary; late work cannot update UI or write output.
- Tests cover all five formats, multiple named outputs, active document, unsaved imports, settings/mapping/data revisions, invalid states, stale and cancelled jobs, overwrite/cancel, external destinations, no-write preservation, Open/Reveal, and webview authority. Root compatibility/report/input/output suites and desktop direct/RPC/component tests pass.
- Performance evidence records host/runtime, fixtures, timings, memory/resource methodology, preview debounce, cancellation acknowledgement/cleanup, serialization, and webview long tasks. Sprint 041's 100,000-row responsiveness exception (including measured >100 ms long tasks) remains explicitly carried to Sprint 043 unless directly remediated and remeasured; no parser benchmark substitutes for UI task evidence.
- Desktop typecheck/Vite build, focused and full applicable tests, browser/component checks, available native-host checks, and `git diff --check` are run and recorded with exact commands, versions, counts, warnings, artifact hashes, screenshots, and unavailable checks. Browser/shim or mock evidence is not represented as native acceptance.
- `planning/state.md`, `planning/decisions.md`, `planning/questions.md`, and Sprint 042 evidence record all format, identity, cancellation, no-write, native-host, performance, privacy, and residual decisions, plus Sprint 043 entry conditions.
- Final status is `COMPLETE`, `COMPLETE WITH RECORDED EXCEPTIONS`, or `BLOCKED`; no native release/platform, Hutch, broad Office, license/Marketplace, or formal accessibility certification is inferred.
